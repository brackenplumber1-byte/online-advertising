# SEO Audit — brackendownsplumber.co.za

**Date:** 5 August 2026
**Site:** https://www.brackendownsplumber.co.za/ (WordPress, All in One SEO Pro v4.9.10)
**Method:** Live crawl of homepage, robots.txt, sitemap index (6 sub-sitemaps, ~90 URLs), 7 area pages, 2 service pages, 1 blog post, plus header/response inspection. No Search Console or Analytics access — findings are based on what's publicly crawlable.

## Headline: this looks like a freshly built/relaunched site
Every blog post in the sitemap is dated **2026-08-04** (yesterday) and area/service pages carry the same `lastmod`. That context matters — several "issues" below are really "make sure this new build gets crawled and validated," not long-standing decay.

---

## 1. Critical — fix first

### 1.1 Duplicate, conflicting JSON-LD structured data on every page
Every page ships **two separate schema blocks** that disagree with each other:

- An auto-generated AIOSEO `@graph` block (Organization + WebSite + BreadcrumbList) with:
  - `"name":"Brackendowns Plumber Brackendowns Plumber"` — the business name is duplicated (looks like a template placeholder concatenation bug).
  - `"description":"Plumbers Alberton"` — thin, generic.
  - Broken/placeholder social profile URLs in `sameAs`: `facebook.com/@brackendownsplumber`, `x.com/@brackendownsplumber`, `instagram.com/@brackendownsplumber`, **`tiktok.com/@@brackendownsplumber`** (double `@`, a dead link), `pinterest.com/@brackendownsplumber`, `youtube.com/@brackendownsplumber`, `linkedin.com/in/@brackendownsplumber` (wrong URL pattern for a company).
- A second, hand-built `Plumber` schema block (theme-injected) with correct data: proper name, full address/geo, real `areaServed` list, a full service catalog, and a clean `sameAs` (Facebook, Instagram, and a Google Business Profile share link).

**Why it matters:** Google's Rich Results system will either pick one block arbitrarily or flag the conflict; the broken `sameAs` URLs can surface as dead links in Knowledge Panel data, and the duplicated business name is a bad look if anyone views page source or if it leaks into a rich snippet.
**Fix:** In AIOSEO, either disable its auto-generated Organization schema (Search Appearance → Schema Markup) since the theme already emits a correct `Plumber` block, or fix the business name field and the social profile URLs so only one clean, consistent schema block ships.

### 1.2 Render-blocking jQuery in `<head>`
`jquery.min.js` and `jquery-migrate.min.js` are loaded in `<head>` with no `defer`/`async`. Every other script (`main.js`, `formlayer`) is correctly placed near `</body>`, so this is one inconsistency, not a systemic pattern.
**Fix:** Add `defer` to both jQuery script tags, or move them to load right before `main.js` at the bottom.

## 2. High priority

### 2.1 Unoptimized hero/content images
The four content photos on the homepage (`job-geyser-roofspace.jpg`, `job-water-meter-valve.jpg`, `job-pipe-excavation.jpg`, `job-ariston-install.jpg`) are **270–315 KB JPEGs each** (~1.2 MB combined), served with no `width`/`height` attributes and no `loading="lazy"`.
**Impact:** Slower LCP, and missing dimensions risk layout shift (CLS) as images load.
**Fix:** Convert to WebP/AVIF (should cut size 60-80%), add explicit `width`/`height`, and lazy-load anything below the fold.

### 2.2 Service page titles run long
`/services/geyser-repair/` and `/services/drain-cleaning/` (and likely the other 14 service pages, same template) have **71–72 character titles** — e.g. *"Geyser Repair & Installation Alberton & East Rand | Brackendowns Plumber"*. Google typically truncates around 580–600px (~60 chars), so these will clip in the SERP, often losing the brand name.
**Fix:** Shorten the template, e.g. `Geyser Repair & Installation | Brackendowns Plumber` (drop the redundant "Alberton & East Rand" — it's already in the meta description and body).

### 2.3 Stale titles showing in current search results
A search-index check for `site:brackendownsplumber.co.za` currently returns some area pages (Randhart, Verwoerdpark, Glenvista, Meyersdal, Brakpan) with **generic titles** ("Randhart - Brackendowns Plumber") that don't match what's actually on the live page today (which correctly reads "Plumber in Randhart | 24/7 Service | Brackendowns Plumber"). This is consistent with the site having just been rebuilt — search engines haven't recrawled yet.
**Fix:** Since this is a new/relaunched site, get it into **Google Search Console** now if it isn't already: verify the domain, submit `https://www.brackendownsplumber.co.za/sitemap.xml`, and use URL Inspection → Request Indexing on the homepage + a handful of priority pages to speed up recrawl.

### 2.4 30 near-identical location pages
The 30 `/areas/*` pages are all 1,390–1,450 words with the same structure, same title/meta pattern, same footer mega-menu — differing mainly by the swapped-in suburb name. This is a legitimate local-SEO pattern (and it's linked and indexed fine), but at this level of similarity it's worth a periodic check that Google isn't quietly canonicalizing/merging some of them in Search Console's "Page Indexing" report (look for "Duplicate, Google chose different canonical").
**Fix:** No urgent action, but budget time to add 1–2 genuinely suburb-specific paragraphs (a landmark, a common local issue like "older Brakpan homes with galvanized piping") to the 8–10 highest-value area pages to strengthen differentiation.

## 3. What's already working well

- **Indexability & crawl setup:** clean `robots.txt`, valid sitemap index with 6 well-organized sub-sitemaps (posts, pages, services, areas, categories), no stray `noindex`, single canonical per page, HTTP→HTTPS and non-www→www redirects both correctly collapse to one canonical host (`https://www.brackendownsplumber.co.za/`).
- **On-page basics:** one `H1` per page, descriptive unique title + meta description on every sampled page, all images carry `alt` text, correct `lang="en-US"`, UTF-8 charset, mobile viewport tag present.
- **Structured data content (aside from the duplication bug above):** rich `Plumber` schema with geo-coordinates, opening hours, full service catalog (16 services), and a proper `areaServed` list covering all 30 suburbs — this is genuinely strong local-SEO groundwork.
- **Internal linking:** homepage/footer links to all 16 service pages and all 30 area pages (nothing orphaned), and blog posts link contextually within the article body to the specific relevant service page (e.g. the "How to Fix a Leaking Geyser" post links to `/services/geyser-repair/` and `/services/leak-detection/` inline, not just via footer).
- **Content depth:** 39 blog posts targeting long-tail, intent-rich queries (PIRB compliance, geyser lifespan, load-shedding effects on geysers, "how to choose a plumber in Alberton") — good topical coverage for a local trade site.
- **Performance basics:** Brotli compression enabled, HSTS + solid security headers (CSP, X-Frame-Options, X-Content-Type-Options), fonts loaded via non-blocking `preload`+swap pattern (a detail many sites get wrong).
- **NAP consistency:** phone number and address match between the visible page and structured data.

## 4. Notes / low priority

- **Google Analytics not firing:** The CSP allow-list includes `google-analytics.com`, but no `gtag`/`googletagmanager` script actually loads — only Ahrefs Analytics does. If GA4 is intended, it's not installed; if it's intentionally Ahrefs-only, no action needed, but worth confirming this was a deliberate choice.
- **TLS handshake is slow:** ~1.5s of the ~2.1s TTFB is TLS negotiation on first connection in this environment; worth a spot-check with a real browser/PageSpeed Insights run since proxied `curl` timing isn't fully representative.
- **404 handling:** returns a proper `404` status for a nonexistent URL — correct behavior, no soft-404 issue.
